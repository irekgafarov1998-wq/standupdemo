# Аудит StandupLab и план передачи проекта

Дата аудита: 27 октября 2026 г.

## Результат

Исходный ZIP содержит полноценный по объёму прототип: веб-приложение React/Vite, сервер Express с Gemini API, а также отдельный Kotlin/Compose Android-проект. Это не означает, что все функции в обеих версиях были подключены к настоящим API или к файловой системе. Внешне развитые экраны часто показывали демонстрационные данные и имитацию операций.

Я внёс изменения в Android-проект под наиболее важный сценарий: **снять выступление → открыть видео → обрезать фрагмент → сохранить новый MP4 в галерею телефона**. Полноценную сборку APK в текущей среде запустить не удалось: Android SDK здесь не установлен. Workflow GitHub Actions обновлён для получения SDK и сборки APK в облаке, но его выполнение в GitHub после загрузки проекта ещё нужно подтвердить.

## Критичные проблемы, обнаруженные в исходнике

| Участок | Проблема | Что сделано |
|---|---|---|
| Точка входа Android | При запуске включался удалённый `WebView` вместо нативных Compose-экранов; приложение зависело от опубликованного URL и интернета | Нативный интерфейс теперь стартует напрямую; неиспользуемый экран WebView удалён |
| Разрешения WebView | Предыдущий WebView автоматически выдавал embedded-сайту все запрошенные разрешения камеры/микрофона без проверки источника | Удалена эта точка входа; медиасценарии выполняются нативными API Android |
| Камера | Предыдущий экран был макетом: кнопка только меняла флаг, таймер шёл локально, файл не записывался; надпись «4K 60FPS» не соответствовала фактической реализации | Добавлена CameraX-запись с сохранением в MediaStore, реальный старт/стоп, переключение передней/задней камеры и редактируемый текст суфлёра |
| Галерея | Отдельной рабочей галереи в нативной навигации не было | Добавлен экран медиатеки и системный импорт видео |
| Монтаж Reels | Таймлайн, waveform, «ИИ-нарезка» и «экспорт» были демонстрацией: ожидание через `delay`, фиктивное сообщение об успехе и отсутствие изменения/создания видеофайла | Добавлены ExoPlayer-предпросмотр, временные границы фрагмента и реальный экспорт обрезанного MP4 через Media3 Transformer |
| Сборка APK | Логи внутри ZIP показывают сбой SDK-шага на устаревшем пакете `tools`; другой лог — падение AAPT2 из-за отсутствующих Android-ресурсов в том запуске | Workflow устанавливает платформу Android 35 и Build Tools 35.0.0 и запускает установленный Gradle напрямую (`:app:assembleDebug`), чтобы не зависеть от отсутствующего `gradle-wrapper.jar` |
| Постоянные данные | В Android есть Room-модели/DAO, но заметная часть экранов использует sample-списки в памяти; `NotebookScreen` имеет пустой обработчик сохранения, FAB создания сет-листа тоже пустой | Не переписывал полностью эти экраны в рамках приоритета видеозаписи; см. остаточные задачи |
| Комната разгонов Android | Ответы в `RiffRoomScreen` зашиты в коде, а не получены от Gemini | Оставлено как прототип; подключение API на Android остаётся задачей |
| Серверная AI-часть веб-версии | При отсутствии `GEMINI_API_KEY` endpoint автонарезки возвращает фиксированные примеры, которые выглядят как результат анализа конкретного видео | Не относится к новому нативному монтажу: в Android AI больше не имитируется сообщением об успешной нарезке |
| Бизнес-логика и хранение | Веб-данные в основном сохраняются локально в браузере; синхронизации аккаунта/между устройствами нет | Не менял веб-схему хранения; перед выпуском необходимо определить модель аккаунта и резервного копирования |

## Что теперь работает в Android исходниках

1. **Камера:** CameraX, получение разрешений, переключение камеры, запись с микрофоном при выданном разрешении, сохранение в `Movies/StandupLab`.
2. **Галерея:** список видео, доступных приложению, отображение названия/длительности/размера, импорт видео через системный Photo Picker.
3. **Монтаж:** просмотр видео, выбор начала и конца, экспорт нового MP4; оригинал не перезаписывается.

Текст суфлёра пока накладывается только поверх live-preview интерфейса, а не прожигается в файл. AI-автовыбор смешных моментов, динамические субтитры, шаблоны/эффекты, публикация в TikTok/Instagram/VK и настоящая работа с социальными аккаунтами в Android не готовы.

## Перед релизом обязательно проверить

- Сборка `assembleDebug` в GitHub Actions и загрузка тестового APK на реальный телефон.
- Камера, микрофон и импорт/чтение видео на Android 8–15, включая отказ в разрешениях.
- Запись ролика 5–10 минут, остановка приложения/поворот устройства, нехватка свободного места, экспорт большого файла.
- Проверка корректности ориентации видео и качества, так как поддерживаемое разрешение зависит от устройства.
- Миграции Room: `fallbackToDestructiveMigration()` сейчас может удалить пользовательские данные при изменении схемы.
- Реальное сохранение шуток/заметок/сет-листов, а не только состояние UI.
- Настоящая AI-интеграция в Android через серверный endpoint. Не встраивать GEMINI_API_KEY в APK.
- Добавить rate-limit, лимиты запроса и валидацию тела запросов к публичным AI endpoint веб-сервера, чтобы не допустить неконтролируемых расходов API.
- Подписанная release-сборка, политика конфиденциальности и корректная обработка пользовательских видео перед публикацией в магазине.

## Как получить APK

После загрузки проекта в GitHub откройте `Actions` → `Build StandupLab Android APK` → выполните workflow. В успешном запуске появится артефакт `StandupLab-Android-APK`, внутри которого `StandupLab-Android-debug.apk`. Это debug-сборка для ручной установки и тестирования, не релиз Google Play.

## Важное ограничение текущего результата

Проверки в этой среде: Android XML разобраны XML-парсером без ошибок; JSON-манифесты и `package.json` проходят разбор; удалённые ссылки на старый Android WebView проверены поиском. Полноценной компиляции Kotlin/Gradle нет: здесь отсутствуют Android SDK и системный Gradle, а сеть для установки зависимостей недоступна. Поэтому не буду утверждать, что APK уже собран или что медиасценарии прошли проверку на реальном телефоне. Следующий необходимый шаг — первая сборка workflow и тестовая установка APK; если сборка выдаст ошибку, лог GitHub Actions даст точное место для следующего исправления.
